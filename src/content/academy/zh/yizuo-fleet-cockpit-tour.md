## 学完你能做什么

打开集群的驾驶舱，不靠猜：知道顶部五个数字在说什么、画布和编排面板在说什么、执行时间线怎么用、每张岗位卡上的状态与按钮怎么用、什么时候需要你去审批队列处理事情，以及「产出」「待命」「空缺」这些词到底指什么。你还能完成第一次建岗，并知道去哪里看每件活儿的来龙去脉。

## 前置条件

- 一个平台账号，登录后左侧导航能看到「集群」。
- 有一个自己的集群最好；没有也能跟着走——本课用一个正在运行的三岗内容集群做例子。

## 先认三个词：集群、岗位、在岗者

集群是一个组织；岗位是组织里的一个稳定职位；在岗者是站在这个职位上的执行者。职位与人对分离：换人不动岗，岗位的定时运行、上级关系、历史产出都保留。本课要读的驾驶舱，就是这个组织的仪表盘。

## 步骤

### 1. 从列表进入驾驶舱

左侧导航点「集群」。列表是你的全部集群（每条标着运行状态与岗位数），右上角「创建集群」新建一个。刚建好的集群还没有岗位，结构视图会提示「还没有岗位，点『建岗』开始组建」。

![集群列表与页面右上角的创建入口](https://cms.finddatatech.cloud/uploads/00_fleet_list_59584c3269.png)

点选一个集群，进入它的驾驶舱。驾驶舱顶部一排按钮管着全队动作：「审批队列」（等你拍板的事）、「全队暂停」「建岗」「归档」「解散」。下面这张图是本课的主战场，先整体看一眼，再逐块拆解。

![驾驶舱顶部：健康块、词汇卡、编排与画布](https://cms.finddatatech.cloud/uploads/01_cockpit_top_abcde482e4.png)

### 2. 顶部健康块：五个数字，一眼知全局

标题下方一排彩色数字，是全集群岗位状态的汇总。鼠标悬停在任何一块上，会给出完整解释：

| 块 | 什么时候亮 | 你该做什么 |
| --- | --- | --- |
| 正常 | 岗位有人、按定时运行干活 | 无需处理 |
| 已暂停 | 集群或该岗位被暂停，到点也不干活 | 想恢复就再到岗位卡上操作解除 |
| 超时未报 | 到点了但没按时交产出（超过容忍窗口） | 点岗位卡上的「产出」或「来源会话」看卡在哪里 |
| 空缺 | 还没绑执行者，或绑的角色已不存在 | 点「换人」补一个在岗者 |
| 待命 | 不排班、不烧钱，等被派活或审批唤醒 | 正常状态，无需处理 |

例子里这个集群：巡线岗正常；内容岗待命——它没有定时运行，等主管派活；源岗已暂停——到点也不干活，直到你在岗位卡上解除。一行数字就能读出全局概况，这正是健康块存在的目的。

### 3. 词汇对照卡：旧词 → 现行词

如果你在早期版本里学过这套功能的旧叫法（报数、拍板、被动……），点开健康块下方的「词汇对照」一行，九组新旧词一目了然：

![词汇对照卡展开：九组新旧词](https://cms.finddatatech.cloud/uploads/03_vocabulary_card_543e1be73d.png)

| 旧词 | 现行词 | 意思 |
| --- | --- | --- |
| 报数 | 产出 | 岗位回合结束后交出的成果与说明 |
| 拍板 | 审批 | 岗位请求你授权后，你做的裁定 |
| 失联 | 超时未报 | 到点了没按时交产出（超过容忍窗口） |
| 待补 | 空缺 | 岗位还没绑执行者，或绑的角色已不存在 |
| 被动 | 待命 | 不排班，等被派活或审批唤醒 |
| 换防 | 换人 | 给岗位换一个在岗者 |
| 节奏 | 定时运行 | 岗位的定时回合（每天几点、每几小时） |
| 日报流 | 最新产出 | 全集群各岗位最近一次产出的时间线 |
| 接棒 | 流转 | 上游岗位完成后，活儿交给下游继续 |

刚接触集群的读者可以直接忽略这行——现行词本身就是最终叫法，界面上只会出现现行词。

### 4. 编排与画布：这个集群怎么协作

词汇卡下方是编排区（图 1 中部）。第一行是这个集群的协作方式与护栏：比如「主管模式」表示岗位之间可以互相派活；「链深上限」「每跳预算」限制一次派发最多传几层、每层花多久，防止失控放大。第二行「派发」写明当前派发许可从哪来：没有逐条声明的连线时写「仅隐式许可」并给出对数——许可来自模式本身，而不是一张显式连线图。

再往下是分布在这一屏的另外三样东西：

- **配置栏**：模型分布（全队按模型计数）、思考深度、上下文预算、边流量（24 小时）——先看全队画像，再决定要不要逐个岗位改；
- **画布**：岗位之间的连线图，节点上是岗位名、在岗者、生效模型与最近一次运行时间，边上的粒子流表示派发/流转真的在发生；
- **「设计」按钮**：进入设计模式手动连边或改边。改动先出草稿差异、经你确认才落地；新建的集群同样要你确认结构之后才启动。

### 5. 执行时间线：这一队人最近都跑了什么

编排区下方是可展开的「执行时间线」：每一行是一次真实回合——状态（成功 / 失败 / 部分失败）、来源（定时运行 / 人工 / 派发 / 事件）、岗位、耗时与 token 数。三个下拉框分别按状态、来源、岗位过滤；点开任意一行，下方「泳道瀑布」把这一回合拆成工具调用的时间条，右上角切换「实时」与「回放游标」，可以逐格回看它当时到底在做什么。

![执行时间线：回合列表与泳道瀑布](https://cms.finddatatech.cloud/uploads/06_execution_timeline_369de22f31.png)

这一块是排查的第一现场：先看有没有失败的回合，点开瀑布看它卡在哪个工具、等了多久，再去岗位卡或来源会话看细节。

### 6. 结构视图：读懂一张岗位卡

结构视图按层级列出全部岗位卡。每张卡从上到下：

![岗位卡（图为另一个三岗集群，卡片结构相同）](https://cms.finddatatech.cloud/uploads/02_post_cards_7200cb941f.png)

- **状态徽章**（卡左上角）：正常 / 待命 / 空缺 / 超时未报 / 已暂停，与健康块一一对应；
- **岗位名与在岗者**：岗位名加粗；「角色」指在岗者是平台里配置的一个角色，「阵列」指一组协同工作的智能体，「Agent 服务」指外部注册的智能体服务；后面是生效模型；
- **定时运行**：如「每天 9:0」；没有定时则显示「待命(无定时,随叫随到)」；
- **最近回合摘要**：一句话说清这一轮干了什么、发现了什么（指标行也在这一带，来自岗位最近一次回合的自报）；
- **按钮**：卡片右侧两颗——「产出」打开该岗位的产出明细（每条产出都带「来源会话」，一键跳回完整对话）；「详情」打开岗位侧栏，内含「配置 / 产出 / 审批」三个页签——换人、暂停、删岗都在「配置」里。

### 7. 最新产出：全局时间线

页面最下方「最新产出」把每个岗位最近一次产出按时间排好，最新在前、异常岗位置顶，每条带状态徽章与岗位名，「来源会话」一键跳转。想知道「最近谁干了什么」，先看这里，不用逐张岗位卡翻。

![最新产出：各岗位最近一次产出](https://cms.finddatatech.cloud/uploads/07_latest_outputs_df343156f8.png)

### 8. 审批队列：什么时候需要你出手

岗位遇到需要你授权的事情（比如要更换凭据、要执行敏感操作），不会自作主张，而是把请求放进「审批队列」，并在驾驶舱顶部横幅提示「等你 N 件」。点右上角「审批队列」，抽屉标题上就带着待裁数量：

![审批队列：一条待裁的示例请求](https://cms.finddatatech.cloud/uploads/04_approval_queue_883b6940da.png)

每条请求写清楚了：谁提的（来源岗位）、什么时候、事情原委、建议时限，以及岗位自己建议的处置。批复后状态变成「已批」；勾选「显示全部（含已裁/过期）」可连同已处理的一起回看。搁置不批的请求会过期，岗位会在之后的回合里继续提醒或换一种做法。

### 9. 第一次建岗

点右上角「建岗」：

![建岗弹窗](https://cms.finddatatech.cloud/uploads/05_create_post_a390739035.png)

- **岗位名**：职位叫什么，用职能命名（如「巡线岗」）；
- **目标类型**：决定「在岗者」里能选谁——「角色」是平台里配置的智能体角色，「阵列」是多个智能体的协同组，「Agent 服务」是外部注册的智能体服务；
- **在岗者**：具体绑谁；
- **上级岗位**：不选就是顶层；
- **定时运行**：选一个定时（每小时 / 每天定时 / 自定义 cron），或保持「待命(无定时,随叫随到)」。待命岗不烧钱，只在被派活或审批唤醒时干活；选了定时之后，下方会出现「回合提示词模板」，即每次定时或唤醒时递给这一岗的指令（一句话即可）。

保存后新岗出现在结构视图里；如果是空岗（没绑在岗者），健康块的「空缺」会加一。

## 自检练习

1. 打开你自己的集群驾驶舱，读出五个健康块的数字，并说出每个数字对应哪类岗位。
2. 展开「词汇对照」，找出「接棒」对应的现行词，再到界面里找到它出现的位置。
3. 在执行时间线里按「失败」过滤，点开一条看泳道瀑布，说出它卡在哪个工具。
4. 打开「审批队列」，确认当前没有等待你的事项；勾选「显示全部」看一眼历史请求长什么样。
5. 给集群加一个待命岗（不配定时运行），观察它计入健康块的「待命」。

## 常见问题

**问：待命和已暂停有什么区别？**
待命是岗位自己的属性：没配定时运行，被派活或审批唤醒才干活，期间不消耗资源。已暂停是一种被叫停的状态：集群或岗位被暂停后，到点也不干活。待命不需要处理；已暂停通常是有人主动操作的结果。

**问：健康块说超时未报，但岗位卡看起来一切正常？**
先刷新页面；若仍不一致，点该岗位的「产出」看最近一次回合的时间——超过容忍窗口的都会被计入。容忍窗口按岗位的定时运行间隔自动给出。

**问：空缺岗会自己干活吗？**
不会。空缺等于职位上没有人，永远不会被唤醒。点「换人」补一个在岗者即可恢复。

**问：审批队列是空的，但我记得批过东西？**
默认只显示等待处理的事项，勾选「显示全部（含已裁/过期）」即可回看已批与已过期的。

**问：怎么让岗位之间自动协作（上游完成交给下游、主管派活）？**
那是「编排」的领域，见下一课；驾驶舱里的「设计」也能手动连边。
