## 学完你能做什么

在 WorkBuddy 里从市场安装一个功能集，并让它的角色读到你的真实数据。完成后三件事同时成立：技能出现在 WorkBuddy 技能页；角色出现在对话页的角色选择器；数据连接可用，且不需要你保管任何密钥。

## 前置条件

| 项 | 要求 | 不满足时的现象 |
|---|---|---|
| WorkBuddy | 5.9 或更新版本 | 插件页没有圆形「+」入口 |
| Node.js | 18 或更新版本 | `npx` 命令报版本或语法错误 |
| 平台账号 | 能通过组织统一登录 | 授权页登录后无法跳回 |
| 一个功能集 | 市场里任意一个带数据引用的功能集 | 第 4 步无数据连接可建立 |

本文用「三员投研团队」举例。换成任何一个功能集，命令与步骤完全相同。

## 术语

本课程全文只用「本课程写法」一列。同一个概念只用一个名字：读者与检索工具都按关键词定位，两名并用会导致对不上。下表左列是概念，右列是本文唯一写法。

| 概念 | 本课程写法 |
|---|---|
| 市场上可安装的能力单位 | 功能集 | 其他同义叫法一律不用 |
| 授权后得到的短期凭据 | 通行证 | 其他同义叫法一律不用 |
| WorkBuddy 读取连接信息的位置 | 连接配置 | 其他同义叫法一律不用 |
| 功能集的来源仓库地址 | 市场源 | 其他同义叫法一律不用 |
| 查看一次对话执行了哪些工具 | 追踪页 | 其他同义叫法一律不用 |

## 步骤

### 1. 区分「安装功能集」与「连接数据」

两者是独立动作，理解这一点可以避免把授权失败误判成安装失败。

- **安装功能集**：把功能集里的技能与角色写入 WorkBuddy。只读取公开内容，不需要身份。
- **连接数据**：让这些角色读取真实数据。需要确认「你是谁」，因此有一次浏览器授权。

两个动作互不阻塞。可以先安装多个功能集，再逐个建立数据连接；安装步骤从来不会因为缺少通行证而失败。

### 2. 添加市场源

**输入**：WorkBuddy 已安装且能打开插件页。
**动作**：在插件页点圆形「+」，选「市场源」，粘贴下面一行，确认添加。

```
FindDataTechnology/facet-marketplace
```

**产出**：市场列表出现该市场源提供的一批功能集。

填 `owner/repo` 简写即可，不需要完整网址。WorkBuddy 读取的是该仓库中的市场清单文件（`marketplace.json`），不是一个网页——这就是它凭简写就能识别的原因。

### 3. 安装功能集

**输入**：第 2 步已完成，市场列表非空。
**动作**：在市场列表中选择目标功能集，点安装。
**产出**：两处出现新条目——技能页出现该功能集的技能；对话页的角色选择器出现该功能集的角色。

安装完成不代表可以读取数据。读取数据需要第 4 步。

### 4. 建立数据连接

**输入**：第 3 步已完成；本机已安装 Node.js 18 或更新版本；可用的平台账号。
**动作**：在终端执行下面这条命令，把 `<功能集ID>` 替换为目标功能集的标识。

```
npx @finddatatechnology/facet auth <功能集ID> --target workbuddy --write-mcp
```

命令分三段执行，每段的预期现象如下：

1. 打印一行「选道」说明，指明本次采用哪种连接方式以及原因。
2. 打开浏览器授权页。用平台账号登录并同意。
3. 把连接写入 WorkBuddy 的连接配置，并把该文件权限收紧为仅本人可读。

**产出**：终端输出「MCP 连接配置已写入」，同时列出被写入的路径与该通行证的有效期。

命令托管通行证而不是让 WorkBuddy 自行授权，原因是当前 WorkBuddy 版本读取用户级连接配置时尚未使用其中的授权字段。由命令完成授权、只把短期通行证交给 WorkBuddy，是当前版本唯一可用的免密钥路径。客户端支持该字段后，同一条命令会自动切换为更简洁的方式，你的操作不变。

### 5. 验证连接

**输入**：第 4 步已完成，终端报告写入成功。
**动作**：新建会话，在角色选择器中选中该功能集的角色，提一个**你已知答案**的真实业务问题；然后打开追踪页，查看这一回合。
**产出**：追踪页出现至少一次数据工具调用及其返回结果。

不要用「你好」之类无答案的问题验证——无答案的问题无法区分「真的读到数据」和「模型编了一段」。

### 6. 续期通行证

通行证有有效期。过期后不需要重新授权，执行下面这条命令。

```
npx @finddatatechnology/facet auth --refresh
```

**产出**：终端输出「已静默续期」，并列出被改写连接配置的路径；其中旧的通行证被新通行证替换。

查看当前通行证的有效期与可续期状态：

```
npx @finddatatechnology/facet auth --status --target workbuddy
```

`--refresh` 会把新通行证写回 WorkBuddy 的连接配置，不需要手工编辑任何文件。它只改写带本平台受众标识的通行证；其他凭据（例如调用键）保持原样。

### 7. 在其他客户端使用同一功能集

市场仓为每个带数据引用的功能集附有按客户端分列的连接说明，路径为 `connect/<客户端名>.json`。该文件写明对应客户端应采用的连接方式与命令。

换客户端时以该文件为准。不要复用其他客户端的连接配置——不同客户端支持的连接方式不同，复用的配置通常不生效。

## 如果没成功

| 现象 | 原因 | 处置 |
|---|---|---|
| 添加市场源后列表为空 | 市场源写法有误，或含有空格 | 重新粘贴 `FindDatatechnology/facet-marketplace` 完整一行；该仓库为公开仓库，无需登录 |
| 终端提示未写入 | 未加 `--write-mcp`，或交互确认时答了 n | 加 `--write-mcp` 重新执行 |
| 使用时提示需要授权 | 通行证已过期 | 执行 `facet auth --refresh` |
| 通行证未过期但仍被拒 | 平台账号缺少该功能集要求的角色 | 联系管理员授予角色；重复重试无效 |
| 浏览器授权页无法打开 | 默认浏览器被拦截插件阻断 | 改用 `--no-open`，命令会打印授权地址，手动在浏览器中打开 |
| 角色可用但工具调用失败 | 角色选择器仍停在通用助手 | 在角色选择器中选中该功能集的具体角色；选中具体角色后，可用工具会收窄到该功能集声明的集合，这是设计行为 |

## 自检

三条全部成立才算通过：

1. 执行 `facet auth --status --target workbuddy`，输出显示通行证未过期，且「可续期」为是。
2. 提一个真实问题后，追踪页出现至少一次数据工具调用。
3. 执行 `facet auth --refresh`，输出包含「已原地改写配置」；随后再次提问仍然正常。

## 下一步

数据连接可用之后，可以把该功能集的角色组合成固定工作流，或让其按节奏自动运行。这属于动手搭建层的内容。
