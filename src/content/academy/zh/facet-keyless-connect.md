## 学完你能做什么

在 WorkBuddy 里从市场装一个功能集，并让它连上你的真实数据——**全程不需要你手抄、粘贴任何密钥**。装完之后，功能集里的技能和角色在 WorkBuddy 里可用，数据连接会在后台自动续期。

## 前置条件

- 已安装 WorkBuddy（5.9 或更新版本）。
- 一台装有 Node.js 18 以上版本的电脑，用来跑一条安装命令。
- 一个平台账号，且能通过组织的统一登录——授权那一步在浏览器里完成，需要你本人操作。
- 想好要接哪个功能集。市场里七十多个功能集，本文用「三员投研团队」举例，你换成任何一个都一样。

## 步骤

### 1. 先分清两件事：装「能力」和连「数据」

这一步值得慢一点，因为它决定了后面为什么是两个动作。

- **装功能集** = 把技能与角色放进 WorkBuddy。这一步只读公开内容，不需要任何身份。
- **连数据** = 让这些角色能读到真实数据。这一步要知道「你是谁」，所以有一次授权。

两件事分开做、互不阻塞：你可以先装一堆功能集放着，之后再逐个连。也正因为分开，第 2–3 步不做身份验证也不会失败。

### 2. 添加市场源（一次性）

WorkBuddy 的市场支持外部地址。打开插件页 → 点右上角圆形「+」→ 选「市场源」→ 粘贴下面这一行：

```
FindDataTechnology/facet-marketplace
```

只填 `owner/repo` 这种简写即可，**不用填完整网址**——客户端会自己去公共代码托管平台取这份清单。这也是它为什么能一眼认出来：它读的是那份仓库里的市场清单文件，不是一个网页。

添加成功后，市场列表会多出这批功能集。

### 3. 装功能集

在市场里找到要用的功能集，点安装。装完检查两处：

- 技能页出现该功能集的技能；
- 对话页的角色选择器里出现它的角色。

**预期现象**到此为止——装完还不能读你的数据，那属于下一步。

### 4. 连数据（一条命令，一次授权）

打开终端，把 `<功能集ID>` 换成刚才那个功能集的标识：

```
npx @finddatatechnology/facet auth <功能集ID> --target workbuddy --write-mcp
```

命令会先打印一行「选道」说明（告诉你为什么用这种方式），然后弹出一个浏览器授权页——用你的平台账号登录并同意。之后它会自动把连接配置写进 WorkBuddy 的配置文件，并把文件权限收紧到只有你自己能读。

**预期现象**：终端显示「MCP 连接配置已写入」，并列出写入的文件路径，以及这张通行证还能用多久。

> 为什么是「代持」而不是让 WorkBuddy 自己授权：当前版本的 WorkBuddy 在读用户级连接配置时，还不会使用里面的授权字段，所以由命令代你完成授权，只把一张短期有效的通行证交给它。等客户端支持了，同一条命令会自动换成更省事的方式——**你的操作不变**。

### 5. 确认真的连上了

别用「你好」验证。新建会话，选中刚装的角色，提一个**你手上有答案**的真实问题。然后打开追踪页看那一回合：能看到它调用了数据工具、拿到了结果，就算通了。

### 6. 到期不用重来

通行证会过期。过期后**不要重新走一遍授权**：

```
npx @finddatatechnology/facet auth --refresh
```

它会静默续期，并把新通行证**写回 WorkBuddy 的配置文件**——原来那条会被自动替换，你不用动任何文件。

想知道还剩多久、能不能续期：

```
npx @finddatatechnology/facet auth --status --target workbuddy
```

### 7. 团队里用别的客户端怎么办

市场仓里每个带数据引用的功能集，都附了一份按客户端分开的连接说明，路径是 `connect/<客户端>.json`。里面有该客户端该走哪种方式、要跑什么命令。

换客户端时照那份文件做，**不要抄同事的配置**——不同客户端可用的方式不一样，抄来的多半不生效。

## 如果没成功

- **添加市场源后列表是空的**：确认填的是 `owner/repo` 简写、没有多余空格。这个仓库是公开的，不需要登录。
- **命令说「未写入」**：加 `--write-mcp` 再跑一次；或在交互提示里回答 y。
- **用的时候提示需要授权**：先跑 `--status` 看通行证是否过期，过期就 `--refresh`。若通行证没过期仍被拒，说明你的账号没有该功能集要求的角色——找管理员加角色，反复重试没有用。
- **授权页打不开或卡住**：换个浏览器，或临时关掉拦截插件重试。也可以用 `--no-open`，命令会把地址打印出来让你手动打开。
- **角色能用但调工具失败**：确认角色选择器里选的是该功能集的角色，而不是通用助手。选中具体角色后，可用工具会收窄到该功能集声明的集合，这是设计不是故障。

## 自检

完成下面三条即算通过：

1. `--status` 显示通行证未过期，且「可续期」为是。
2. 提一个真实问题，追踪页里能看到至少一次数据工具调用。
3. 跑一次 `--refresh`，输出里出现「已原地改写配置」，之后再提问依旧正常。

## 下一步

数据通了之后，可以把这个功能集里的角色组合成你自己的固定工作流，或者让它按节奏自动跑起来——那是「动手搭建」层的内容。
