## Context

站点是 Astro 静态站，样式集中在单文件 `public/global.css`（542 行，`:root` 自定义属性
即 token 层），无框架、无 Tailwind；全站除 `/indicators` 的图表脚本外没有 JavaScript。
视觉身份见工作区根 `DESIGN.md`（「Agent's Console」：midnight-ink `#0b1020` 底、
terminal-mint `#38e1c8`、periwinkle-signal `#6aa6ff`，含一套未被使用的阴影词汇）。
三条兄弟产品线在代码里已有各自的印章母题（识律 `SealMark.tsx` 朱砂 `#a6402f`、
谦面 `SiteMark.tsx`、萬星 `SiteMark.jsx`），壹座与柏讯没有；全工作区没有可用的产品截图。
参见 proposal.md — Why。

## Goals / Non-Goals

**Goals:**

- 在不动身份（深色 + 薄荷）的前提下，让层级、材质、节奏读出"公司门面"而不是"文档站"。
- 让首页 hero 与 `site-shell` / `product-portal` 的现行要求一致（见 specs）。
- 把三个可复核的呈现缺陷修掉，且修复方式可被后续检查复用。
- 让"产品"这件事在页面上有形：五个线标 + 每线一张示意。

**Non-Goals:**

- 不重做视觉世界（不换底色、不换品牌色、不引入插画/摄影）。
- 不使用真实产品截图（手上没有干净的，且会随产品漂移、可能泄漏数据）。
- 不改路由、slug、构建期数据管线；不新增页面。
- 不处理内容真值与 npm/产品站标识（分别归 `official-web-content-truth` 与独立待办）。

## Decisions

**D1 · 配色角色重排，而不是换色。** 薄荷 `#38e1c8` 成为唯一品牌强调（CTA、数字、当前项）；
蓝紫 `#6aa6ff` 降级为内文链接色；区块标题改用近白 `--text`。新增两个层级 token：
`--surface-raised`（feature 卡）与 `--border-strong`（hover / 当前项）。背景允许 ±5% 内
微调。_备选_：蓝紫为主（与多数暗色站同质）、整体换配色（破坏已上线的线色关联）。

**D2 · 只给拉丁引入显示字体，中文继续系统字体。** 判据：仅拉丁、woff2 ≤ 80KB、开源许可、
与中文混排基线稳；只作用于标题与 kicker。_备选_：全系统字体（零成本但标题无性格）、
中文 webfont（子集化后仍可能 200KB–2MB，收益不抵成本）。最终选型见 Open Questions。

**D3 · 材质分三级，启用既有阴影词汇。** feature 卡（带阴影/渐变）、标准卡、行式列表。
_备选_：保持单材质只调节奏（改动更小，但"文档站观感"的根因就是单材质）。

**D4 · 线标用阶梯字（壹/识/柏/谦/萬），官网统一墨色。** 序列感是这套命名最大的资产，
官网把它显式化；各线自己的产品站保留各自的印章与线色。由此确定分工：
**官网 = 序列化表达，产品站 = 个性化表达**。识律产品站的「律」字印与官网阶梯字不一致，
记独立待办，不在本变更内改动线上产品标识。_备选_：名字字（与产品站冲突）、各线自带色
（五个色相争）、纯文字胶囊（无序列感）。

**D5 · 导航收窄到六项 + 页脚分组，零 JS。** 主导航 = 产品 / 数据 / 仓库 / 文档 / 动态 / 演示
（+ 语言切换）；`indicators`、`roadmap`、`releases` 下沉到页脚分组与对应落地页入口。
中文标签「项目」→「仓库」（`CONTEXT.md` 把「项目」列为该避开的工程语境词，`/repos`
的正式说法是仓库）。不新增页面、不改路由。_备选_：保留十项只做视觉分组（拥挤仍在）、
引入 JS 下拉（破坏零 JS 特性，用原生 `<details>` 可以零 JS 达到同样效果）。

**D6 · OG 图用静态资产，不引入生成服务。** 中英各一张 1200×630，用现有 CSS 视觉搭一版
HTML 再截图导出。规格只要求"每页声明 og:image"，资产过期属例行维护。

**D7 · `/repos` 的线归属放本地小表。** 与 `FEATURED` 同性质，随仓提交；缺归属的仓库进
「其他」分组而不是被丢弃。_备选_：继续依赖 GitHub 描述里的 `[wire]` 前缀（把内部分组信息
塞进对外文案——正是 `official-web-content-truth` 要清掉的东西）。

**D8 · 零 JS 与无障碍作为可验收底线写进规格。** 新交互一律 CSS 或原生元素；文本对比度
≥ 4.5:1、大字与图形 ≥ 3:1；动效受 `prefers-reduced-motion` 约束；可交互元素有可见焦点。

## Risks / Trade-offs

- [token 层是全站性的，可能出现意外溢出或对比度回退] → 批次一先在本地对全部页面做桌面/移动
  截图核对，再上线；上线后中英对照截图归档到 `reports/`。
- [拉丁显示字体与中文混排基线不齐] → 只用于标题与 kicker，中文继续系统字体，必要时用
  `font-size-adjust` 与行高兜底。
- [官网阶梯字与产品站印章被读作不一致] → 明确"官网序列化 / 产品站个性化"的分工并写进
  design 与 `CONTEXT.md`；识律对齐记为独立待办。
- [`/repos` 分组依赖本地线表，新仓会被漏掉] → 缺归属进「其他」而非消失；把"新仓是否已归线"
  列为发布前检查项。
- [OG 图是静态资产，随产品变化过期] → 记入发布节点复核，不作为阻塞项。

## Migration Plan

- 批次一：本地全页截图核对 → Jenkins 构建 → Harbor → ArgoCD 滚动 → 线上中英对照截图归档。
- 批次二：同上，另加 `og:image` 探针与五个线标的线页截图。
- 回退：镜像 tag 回滚（ArgoCD 指回上一 tag），必要时切现成的 `dist` 静态兜底。
- 两个批次各自带线上证据，便于单批回退。
