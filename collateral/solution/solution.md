# 寻数数据整体解决方案

> 用自然语言提问，拿回真实数据行——更完整的说法是：**让 AI 智能体团队替你持续处理数据**。

## 一、理念篇：我们怎么解决数据问题

数据难用，难在三处：找不全（数据散在千百个源和接口里）、对不上（每个库各有各的口径）、留不住（租来的平台一停服，资产就断根）。寻数的解法是一条通路、四个坚持：

**一条通路**：数据从源到可用，走完整一条自助路——

```
[数据源]      [采集·数据包]     [语义本体]              [MCP 网关]      [智能体集群]     [看板/报告/API]
  世界    ──►  可装·可审计   ──►  一个本体·统一口径  ──►  500+ 工具  ──►  持续运行·自汇报 ──►  你用的产出
               每源一个包         semantic_observations   自然语言可达     壹座建管·萬星上线
```

**四个坚持**：

1. **自然语言可达**——每个能力都是 AI 智能体可以调用的工具（MCP），不是只有工程师能学的库 API。问一句话，拿回真实数据行。
2. **一个本体**——所有数据源统一落进同一个语义 schema（`semantic_observations`），指标、区域、时间一套口径。跨源对得上，不是千个接口各说各话。
3. **数据源即包**——每个数据源是独立可安装、可审计的数据包；身份即契约，命名与结构有规范约束，质量有对账门把关。
4. **数据留在你手里**——一条命令装进你自己的机器，本地文件、不绑云账号；全栈可私有化交付进你的机房。

我们以此自律：**只讲可验证的话**。本文全部数字为实测口径，每个场景都有可点开的证据。

## 二、架构篇：五条产品线，一个生态

| 线 | 定位 | 一句话 |
|---|---|---|
| **壹座 Base** | 集群平台（宿主与旗舰） | 组建、管理、迭代、分享你自己的智能体团队，长期在线 |
| **识律 Lex** | 文本整体解决方案 | 处理与文本有关的内容：法律、论文、思想、剧本 |
| **柏讯 Wire** | 数据整体解决方案 | 让 AI 替你读世界：从数据源到可用数据的一条自助通路 |
| **谦面 Facet** | 技能与发布的供给面 | 打通主流市场，并让主流 AI harness 直接可用 |
| **萬星 Constellation** | 运行时 | 把团队上线运行：部署、驻留、门面、计费、机群观测 |

架构一句话：**壹座建管、萬星上线运行**。集群（持续运行的智能体团队）归属壹座，按业务场景跨线编排；识律、柏讯、谦面是供给域，各自独立成线、独立售卖。

三个价值锚：

1. **团队是一等公民**——不是「一个会话挂几个专家」，而是一支会自己干活、自己汇报、自己进化的组织。
2. **不锁平台**——同一套智能体、技能与 MCP 供给可以装进主流 AI harness（Claude Code、Cursor 等）直接使用。
3. **可自托管、可私有化**——一条命令装进你自己的机器；全栈可交付进客户机房。

## 三、实证篇：实测口径

以下数字全部为公开可核的实测口径（每个随系统变化的值带 as-of 与出处）：

- **开放数据本体**：452 个指标概念 / 6 个数据源 / 87 个 MCP 工具（as-of 2026-11-22，工具数取自实例 `tools/list`）——自然语言查询返回真实数据行（官网 /demo 实时可验）
- **统一 MCP 网关**：10+ 个 Server 在册 / 500+ 工具（持续增长量，只报门槛，精确值以台账为准）
- **统一指标注册**：5 万+ 条（持续增长量，只报门槛；精确值与取得日期见口径表）
- **识律·良律**：约 3,700 万篇裁判文书（截至 2026-10-08）/ 32,296 部法规目录 / 合同工具数见网关台账
- **承载模型**：单集群可托管上万智能体（分层承载：冷会话落盘近零内存、温态共宿摊销、真并发按 worker 槽弹性配比）

> 口径纪律：随系统变化的数量一律给 `as-of` 与出处；持续增长量只报门槛形式（「500+」「5 万+」），因为精确总数交付即过期。

我们不展示无法当场验证的数字：没有虚构的案例陈述，没有拍脑袋的增长曲线。

## 四、场景篇：五个通用场景

以下每个场景都指向真实存在的产物或环境，可现场验证。

### 场景一：自然语言问数，返回真实数据行
一句话（如「中国 GDP 2023」）→ 网关 `ai_search` → 返回带单位、频率、来源的指标与数据行。
**证据**：官网 [www.finddatatech.cloud/demo](https://www.finddatatech.cloud/demo) 实时查询框（2026-11-05 冒烟实测返回真实绑定行）。

### 场景二：从数据源到可用数据的自助通路
上传数据 → 自动入指标目录 → 生成质量画像 → 编排变换管线，全程在控制台自助完成。
**证据**：[wire.finddatatech.cloud](https://wire.finddatatech.cloud) 指标目录（5 万+ 指标免登可搜）；三档试用号走查路径见《演示指南》。

### 场景三：持续运行的智能体团队
组建一支长期在线的 agent 团队——政策盯梢、情报巡线、看板值守——按节奏跑、出报告、异常升级到人。
**证据**：[demo.finddatatech.cloud](https://demo.finddatatech.cloud) 免登沙箱可直接对话体验；壹座生产环境在役（2026-11-05 冒烟 200）。

### 场景四：主题看板——指标到仪表盘
从指标本体出发，搭出可刷新的主题看板：宏观周期、六国对比、A 股财报截面、区域经济与省级系列。公开看板 23 块（as-of 2026-11-22，取自柏讯公开看板接口）。
**证据**：[wire.finddatatech.cloud/showcase](https://wire.finddatatech.cloud) 公开看板（接口实测 23 块）；构建源 `dashboards/`；演示视频《看板搭建 150s》。

### 场景五：行业对账模板——泛企业软件的行业可用形态（ERP 板块）

一个行业无关的复式账本内核，加两个行业模板（跨境电商、餐饮连锁）。行业差异全部上移为**模板资产四件套**（连接器 pack + 舰队蓝图 + 科目映射 pack + 报表 preset），整体安装、各件独立升级——这也是柏业服务包**实施档**的上架物形态：客户首单驱动首个行业模板与首个 POS 厂商适配器的落地顺序。

实测口径（2026-11-07，全部可核）：

- **账本内核**：8 件 MCP 工具（写路径只出 proposal、确认门唯一落账）；借贷必平由数据库约束强制、分录 append-only；真 Postgres 测试 44+2 用例全绿。
- **通用科目最小集**：12 个内核科目（资产 4 / 负债 2 / 权益 2 / 收入 1 / 费用 3），行业无关；行业科目经映射 pack 在呈现层对齐，**替换映射不改账**（分录逐字一致，仅报表口径重算）。
- **跨境电商模板**：Shopify 读面（复用已采纳 a1-x-tech/mcp-shopify-admin）+ 国内平台经营数据（淘宝/天猫/京东经连接器实名 provider；拼多多如实不提供）；订单-收款-库存按**能力矩阵**决定几方对账——不可得腿显式标「不可得」并给原因，**不出零差异冒充已核对**；四类差异双侧原始引用；折算汇率须 ecb-exr 出处，无出处不折算；payouts/佣金/手续费独立维度。**当前能力实底**：内圈全部为「需一次接入」而非已接通（Shopify 有动作无真实读取记录 <!-- capability:shopify.orders=unmapped -->，结算面待补 payout 动作 <!-- capability:shopify.settlements=unmapped -->，国内平台需先有一次接入 <!-- capability:taobao.orders=unmapped -->，拼多多不提供 <!-- capability:pinduoduo.orders=unavailable -->）；测试店合成数据全链真跑（接入→对账→差异→拍板→回写落账）可计数断言全过。
- **餐饮连锁模板**：门店主数据确认车道（门店/POS 终端/收款商户号/外卖店铺 + 开停业生命周期 + 加盟/直营标注）；POS BYOK 适配器框架（厂商逐个上线、未适配如实报出 + 导出文件替代通道）；门店三方对账与日结日报三段（流水/收款/差异）；分成只出双方可核对的**分成对账单与核对指令**（对接持牌分账通道的输入数据）。
- **模板边界（机械化审计）**：模板层零旁路账本、零直连库表、回写仅经内核 proposal 白名单车道（确认门只在拍板席位）、连接器对外部系统零写入——四条边界由边界审计器静态证明，随测试全绿。

**守界如实**：资金归集/代收代付/分账执行不提供（二清红线，资金走客户自选持牌通道）；开票/税务申报不自研（挂账）；中央厨房/采购/BOM/排班/会员等重域当前不提供（后续渐进）；POS 未适配厂商不以人工补录冒充自动接入。

**证据**：本仓库 `fd-erp-vertical-templates/`（模板包 + 四件套资产；测试全绿以仓库实测为准，不在此写死条数——该条曾写死具体项数而后失准）；ERP 板块章程见官网 `/erp` 与 `/zh/erp`（边界如实口径页）。谦面市场 live 上架属部署步骤，按挂账处理。
